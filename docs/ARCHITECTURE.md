# 架构说明

```
                    ┌──────────────────────────────┐
                    │        serv00 服务器           │
                    │                              │
  你的域名           │   MX ──▶ serv00 邮件系统       │
 (DNS 在 serv00)     │   ┌────────────────────────┐ │
                    │   │ 真实邮箱 / 别名+catch-all│ │
                    │   └──────────┬─────────────┘ │
                    │              │ IMAP(993)/SMTP(587)
                    │   ┌──────────▼─────────────┐ │
                    │   │  FastAPI 后端 (1 进程)  │ │
                    │   │  - REST API            │ │
                    │   │  - IMAP IDLE 监听线程   │ │
                    │   │  - 面板自动化开邮箱     │ │
                    │   └──────────┬─────────────┘ │
                    │              │ SQLAlchemy    │
                    │   ┌──────────▼─────────────┐ │
  用户/第三方 ──────▶│   │  MySQL (serv00 提供)   │ │
  HTTPS             │   │  用户/邮箱/APIKey/配置  │ │
                    │   └────────────────────────┘ │
                    │   ┌────────────────────────┐ │
                    │   │  nginx 静态前端 (Vue)   │ │  0 进程
                    │   └────────────────────────┘ │
                    └──────────────────────────────┘
```

## 数据流

- **收信**：外部 → serv00 MX → 邮箱；后端通过 IMAP 读取（IDLE 实时 / 按需拉取）
- **发信**：API → 后端校验 `allow_send` → serv00 SMTP 发出
- **开邮箱**：
  - 方案 A：后端登录 serv00 面板 → 调 `add_mailbox` 接口 → 密码 Fernet 加密存库
  - 方案 B：本地 DB 记一条别名记录（依赖 catch-all，无需调面板）
- **取验证码**：后端用存下的凭据（方案 A）或主邮箱凭据（方案 B）连 IMAP → 取最新邮件 → 正则提取 → 返回

## 为什么这样设计

1. **全部放 serv00**：离邮件服务器最近（内网延迟），1~2 进程、<200MB 内存，自用绰绰有余
2. **后端无状态化**：所有状态在 MySQL，哪天搬到 VPS 上跑，一行代码不用改（本来就是标准 IMAP/SMTP）
3. **凭据托管**：调用方只有 API Key，邮箱密码由后端持有，降低泄露面
4. **面板自动化隔离在 provision/panel.py**：serv00 面板改版只修这一个文件
